# Windows payload inventory lists bytecode the installer never writes

Topic: `native-distribution`

Status: **Open — observed in 0.7.0 and 0.7.1 ARM64 candidates; harness tolerates it.**

## Observations

The Windows candidate `payload.json` is generated by
`desktop/scripts/verify-windows-installed.ps1` after it runs the bundled CLI.
Running it creates 35 `mc-cli/python/**/__pycache__/*.pyc` files, and those
files end up in the inventory. A fresh per-user install writes none of them,
so checking a fresh installation against the exact file set fails.
`tests/windows/browser-installed.ps1` now treats inventory entries matching
that bytecode-cache pattern as optional, so it no longer fails for this
reason.

## Proposed repairs

- Generate the inventory before running any bundled interpreter, or exclude
  `__pycache__` from it, so the inventory matches installer output exactly.
- Alternatively, set `PYTHONDONTWRITEBYTECODE` for verification runs of the
  bundled CLI, and remove the harness exception once candidates are clean.
