# macOS shared surface adoption

Topics: `shared-resident-core`, `access-admission-and-pause`

Status: **Ordinary packaged slice passed; streamed CDP and protected-helper
composition remain open.** This follows the bounded Windows acceptance in
[Tactical 153](153-unified-permissions-and-handoff.md).

## Objective and motivation

Bring macOS onto the same Desktop/Browser access and handoff experience as
Windows and the reference target. The user requested an autonomous Windows →
macOS → Linux migration, keeping Python clients and removing duplicated middle
layer policy instead of preserving competing legacy grant engines.

## Completion conditions

- One packaged, pinned TypeScript/Node authority owns ordinary consent, task
  approval, announcements, queues, deliberate takeover, cooldown, profile
  selection and CDP session lifetime.
- Swift supplies native identity, console/readiness/input facts, operator UI,
  provider effects, audit and the independent protected-helper safety ceiling.
- Off, Ask first and Automatic work independently for Desktop and Browser;
  Browser includes supported CDP and JavaScript operations.
- Real packaged Settings and native notices exercise admission, deferral,
  resumption, independent pauses, Stop and profile selection on a claimed Mac
  appliance. Owned fixtures supply independent effect evidence.
- Process, native identity, stale-generation, protected watchdog and renewal
  regressions pass. Protected effects require their own composed acceptance;
  ordinary UI success does not qualify them.
- Restore original app/policy/operator state, reap owned test processes, verify
  credentials and restore the declared target power state before release.

## Boundaries

No Python language rewrite, public operator endpoint, authority restoration
from old grant files, TCC database edits, primary-browser test profile, outer
host input, new VM or publication. Native protected administration under an
explicitly installed managed-appliance policy remains a separate typed plane;
it does not supply ordinary workstation task ownership. Physical HID,
multiple-display privacy, Intel execution and signed distribution are separate
qualification dimensions.

## Ordered work

### 1 — connect the shared policy child

Use explicit packaged paths and a cleared environment. Drain replies and
stderr independently of operator/main-queue event delivery. Bound framing,
requests, event/write queues and deadlines. EOF, malformed frames and blocked
writes terminate/reap the exact child without replay or authority restoration.

### 2 — replace native ordinary policy

Replace Swift admission, target-wide grant restoration and its CDP endpoint
engine with native adapters to v2. Bind each control connection to exact
surfaces, operations, profiles and current session/resource generations.
Keep native console consent identities separate between Desktop and Browser.
A queued ending event must match the session it ends, including after Resume.
Renewal acknowledges the protected helper before extending shared ownership,
within the original consent ceiling.

### 3 — present the same operator experience

Expose independent modes and exact profiles in packaged Settings and the
standalone menu. Native task notices do not activate the app. Capture the
presented intent in each action. Use deliberate key/button/scroll input for
takeover; pointer movement alone does not interrupt. Keep read-only discovery
and Browser work available while native menus screen desktop effects.

### 4 — qualify packaged composition and cleanup

Run the real pinned child in Swift adapter tests, shared policy/reference
conformance, the native static smoke suite, production packaging and Settings
presentation tests. Exercise the actual installed bundle through an independent
native observer; never add a product approval hook to simplify acceptance.
Keep raw UI, target identity, endpoints and diagnostic evidence private.
