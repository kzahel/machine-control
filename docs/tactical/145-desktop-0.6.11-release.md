# Desktop 0.6.11 release

Owning topics: [native distribution](../../topics/native-distribution.md),
[host control](../../topics/host-control.md),
[Mac locked use](../../topics/macos-locked-use.md).

Status: **active**; release preparation authorized after the development
qualification recorded in [Tactical 141](141-desktop-control-reliability-plan.md).

## Objective and completion conditions

Publish desktop 0.6.11 for all six packaged architectures. Include remembered
access choices, native multiline/covered-browser repairs, startup handoff,
guardian diagnostics and negotiated owner renewal. Require the successful
unified candidate and acceptance of its exact signed Mac ARM64 bytes at the
same clean source before dispatching publication once.

## Boundaries

Development-bundle results cannot substitute for the release receipt. Keep
concrete targets, credential locators and raw evidence private. Do not install
over the controller's app, overwrite release assets or wait for publication.
Physical and SIP-enabled qualification gaps remain explicit.

## Ordered work

1. Commit the implementation and versioned changelog on main, then push.
2. Build the unified candidate and authenticate its Mac ARM64 artifact.
3. Run the composed claimed acceptance campaign at the exact clean source,
   including actual 900-second expiry, 960-second renewable ownership, faults,
   visible choices, actual cold boot and verified workspace disposal.
4. Invoke the release script with that candidate and receipt once. Report
   publication queued; CI owns verification and automatic publication.

## Validation and result

Tacticals [142](142-saved-access-choices.md),
[143](143-covered-control-diagnostics-and-acceptance.md) and
[144](144-renewable-control-owners.md) own development/source evidence and limits.
The exact CI-candidate gate remains to be executed for this release. Runtime
qualification uses the target-resident path and does not require a focused VM
window or controller input. Private receipts and workflow records retain the
subsequent candidate/acceptance identities.

The first candidate built and signed Linux packages, then correctly refused
their new browser presentation module because the final-container allowlist
had not been updated. Require that module from 0.6.11 in all three platform
verifiers and exercise presence/omission for both Linux architectures and
containers. Rebuild the unified candidate at the repaired source; the failed
candidate cannot qualify publication.
