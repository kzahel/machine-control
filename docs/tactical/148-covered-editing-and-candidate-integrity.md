## Reproduction and repair

The baseline uses unchanged signed desktop 0.6.11, identifying source revision
`b40cf33`, on ARM64 Tart/macOS 26.6.2 with SIP disabled and one virtual display.
Ordinary and covered AppKit/browser input, Unicode/multiline model/Save/reload,
unfiltered concealment and completion pass. During renewable-owner sampling,
a status call takes approximately twelve seconds and returns no
`coveredSession`; the test raises `KeyError` and cancels its owner. The final
guardian diagnostic has healthy predicates and a cancellation ending. This
does not reproduce the historical guardian fault.

Post-failure signature verification fails and the candidate manifest differs
from staged input. A separate signed scratch-copy comparison isolates a real
test defect: invoking the same bundled adapter without Python's bytecode guard
creates 41 cache files and invalidates its code seal. Removing only those
generated caches restores validity. The equivalent `-I -B` invocation creates
zero caches and retains the signature. Both trials use an unsupported command
that refuses before resident contact. A direct bundled-Python SDK import
separately creates 62 cache files; its guarded control also stays unchanged.

The existing installed CLI already suppresses bytecode. The diagnostic's direct
SDK/adapter path bypassed that entry point and depended on inherited process
configuration. The repair explicitly protects both interpreters. No signature
validation or protected-control enforcement is relaxed. The baseline did not
retain its exact file delta; the paired comparison establishes the unsafe
route, rather than attributing every historical helper delay to cache writes.

A controller-side scratch copy refuses app-bundle cache writes under its own
OS policy and does not reproduce the corruption. Keep that negative result
separate from the permissive dedicated VM, rather than assuming identical
filesystem policy. Scratch copies are removed after each guest comparison.
