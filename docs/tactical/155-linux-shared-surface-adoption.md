# Linux shared surface adoption

Topics: `shared-resident-core`, `access-admission-and-pause`, `linux-desktop`

Status: **In progress**, after bounded Windows and macOS acceptance.

## Objective and motivation

Complete the requested Windows → macOS → Linux migration without rewriting
Python clients. Replace the Linux companion's ordinary grant, approval and
singleton browser policy with the same pinned TypeScript/Node authority used
by Windows, Mac and the fast reference target. Preserve native Linux facts,
AT-SPI effects, compositor-mediated sharing and inherited operator authority.

## Completion conditions

- One bounded, owned child supplies v2 surface consent, task admission,
  announcements, independent pauses, deliberate takeover/cooldown, exact
  browser profiles and streamed CDP lifetime. Replaced Python engines are gone.
- The production Unix peer and live owner channels authenticate their actual
  OS peer, enforce ordering and generations, and terminate on transport loss.
- The real Settings and native GTK notice expose independent Off/Ask first/
  Automatic modes, exact profile choices, warning, approval, deferral, Resume
  and Stop. Restart restores no live authority.
- Native physical-input facts are honest. Movement alone is not takeover;
  unknown observation blocks disruptive admission. Ordinary desktop effects
  continue to use AT-SPI/portal, never appliance root virtual HID.
- Real browser and native fixtures demonstrate independent effects, ownership,
  refusal, pause/Stop, stream revocation, lock/session loss and clean restart.
- Native tests, packaging and platform smoke pass. Restore app/preferences/
  native setup, reap owned processes/staging, restore initial Off and release
  the exact target claim. Record unsupported qualification dimensions honestly.

## Boundaries and native decisions

Keep Python for the provider, native peer credentials, GTK/GLib and platform
transport. Do not translate shared policy into Python. Protected login/unlock
is not claimed for the ordinary Linux desktop profile. Portal sharing remains
an explicit compositor permission and closes on lock/session loss.

**Proposal:** a separate, explicitly installed read-only native activity
observer may be needed on GNOME Wayland, which supplies no existing qualified
ordinary-user global physical-input feed here. It must expose only bounded
health/generation/activity facts for the active local console, discard key and
pointer content, reject virtual injection sources, and fail unknown on loss or
overflow. It must never grab devices, inject input, provide root execution or
silently select the appliance input broker. Qualify this boundary before
reporting human input as ready; prefer an existing native route if investigation
proves an equally complete ordinary-user observation facility.

No new VM, outer console automation, private endpoint in Git, publication,
primary-browser temporary profile, CLI language rewrite or parallel policy
implementation is included.

## Ordered work

### 1 — host the same policy process

Package the pinned runtime and licenses, clear its environment, bound frames,
queues and deadlines, drain replies independently of GLib and reap exactly the
owned child on failure. Prove framing and actual shared-policy behavior.

### 2 — adapt native facts and live channels

Preserve Linux UID/process/session identity and native effect generations.
Translate operator commands and readiness, observe deliberate physical input
honestly, and keep provider dispatch fenced across Stop and late completion.
Expose local and authenticated remote live channels without an authority
fallback or effect replay.

### 3 — replace browser and operator coordination

Authenticate concurrent native-host peers, transport them into the shared
profile registry, route exact approved IDs and retain stream authority checks.
Use shared Settings and native GTK prompts for the same handoff model.

### 4 — qualify the packaged Linux composition

Use the claimed existing appliance, independent native/browser fixture effects
and the public common client. Verify restoration and final Off/claim release.
Native execution, package construction, signed distribution, physical hardware
and other compositor/architecture coverage remain distinct evidence levels.


## Execution record

**Current — process boundary:** the Python transport hosts the actual pinned
child with no environment override or system-Node fallback. Frames, pending
calls, event/writer queues and reply/write deadlines are bounded. Replies and
stderr progress independently of GLib. Failure fences/reaps the exact child
without restart or replay. Six portable checks cover real shared consent /
owner / Stop behavior, cleared environment, malformed/truncated replies,
reply timeout, blocked writer and stderr flooding. Existing Linux native
static checks pass. Packaging now stages the architecture-matched pinned child
and licenses; CI installs its locked dependencies explicitly. This does not
claim the legacy Linux companion has cut over or passed new native UI tests.

**Current — native preflight:** the existing accepted ARM64 appliance is
independently ready under an exclusive claim, with outer UI prohibited. Its
ordinary user cannot read any input event node; no physical-input readiness is
claimed from the old semantic/input APIs. Native build tools will be staged
for this task on the existing appliance. No VM or clone is created.
