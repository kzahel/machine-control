# Native outer desktop admission

Status: source and transport fixtures implemented; live provider acceptance
pending. Owning topics: [access admission and pause](../../topics/access-admission-and-pause.md),
[inner-first routing](../../topics/inner-first-routing.md) and
[target-use claims](../../topics/target-use-claims.md).

## Objective and completion conditions

Make explicitly authorized host-interfering VM input contend with physical
host control on one native desktop. Borrow the already-owned exact VM claim;
never acquire a second VM holder. Recheck both authorities at activation and
actual native effects, fence stale geometry, release held buttons on pause and
report unsupported routes without falling back around the gate.

Complete acceptance needs independent live guest effects and host interference
observations on a controller whose exact provider policy permits outer use.
Socket fixtures alone do not establish those native provider outcomes.

## Boundaries and ordered work

### 1 — classify actual host interference

Route Tart global HID input and UTM global drag through the native host desktop.
Keep UTM VM-directed keyboard/click injection and capture-only routes on their
existing exact-target/disruptive policy path. Resident VM use acquires no host
foreground, cursor or keyboard reservation. Retain absolute prohibitions,
declared attendance, candidate guards and target selection; no silent fallback.

### 2 — borrow exact VM authority at the native effect boundary

The authoritative adapter derives a private binding from its existing claim,
provider resource, generation and verified VM/window geometry. The native
channel validates the owner-only claim store and claim/queue liveness. Native
acceptance and each input primitive acquire that store's operation lock,
validate the existing disruptive lease, then execute under the native desktop
owner fence. No new VM lease or authority renewal occurs.

Bind Tart's visible runner through kernel process arguments to its exact VM.
For UTM, the adapter verifies its pinned UUID/name before the native finite
window/process/geometry binding. Refuse locked host, ambiguous windows, changed
geometry/focus, stale references and expired/replaced claims before delivery.
This is the existing cooperative same-user controller profile, not authenticated
integration authority or distributed-controller arbitration.

### 3 — support cancellable clients and release partial input

Add `OuterSession` with negotiated borrowed-claim support, polite native waiting,
fresh window discovery and single typed input primitives. A focus-settling delay
holds no claim lock; the following input rechecks all conditions. Drag has owned
start/move/end state; pause/disconnect releases only its held button. Session
interruption invalidates window references. No action is replayed.

The bridge supports printable US-keyboard text, Command/Shift chords, click and
drag. Credential input requires a verified field and separate secret transport;
`type-secret` now refuses before reading bytes instead of bypassing Pause.
Control/Option/Fn diagnostics remain unsupported by the new typed bridge.

## Validation and current result

**Current:** 125 Swift tests include real native socket arbitration for two VM
borrows and one physical contender, a separately counted provider effect, pause
fencing and fair handoff. Claim-file fixtures cover atomic effect locking,
unchanged VM ownership, replaced/expired lease, stale references, geometry,
focus, console, lock contention, queue heartbeat expiry and held-button cleanup.
The provider callback in these fixtures is injected; it is not a real Tart or
UTM effect oracle.

Five SDK cases cover negotiation, legacy-provider refusal, no replay on claim
interruption, paused deadline, and physical ASCII mapping. The full 176 common
client tests pass. Mac/Linux static smoke, source-native Mac deployment and
readiness are checked before the implementation commit. Concrete claims,
credentials, target identity and raw evidence remain private.

**Open:** actual outer provider effects and native host non-interference/cleanup
acceptance; credential field/transport; diagnostic modifier qualification;
stronger caller admission from Tactical 071. Preserve the coordinating plan's
remaining protected-resumption and platform acceptance gates.
