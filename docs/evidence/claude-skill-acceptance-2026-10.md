Date: 2026-10-15. **Current, bounded live evidence.**

workflows after a separate fresh Claude session followed the repository
[guide and skill](../../info/claude-computer-use.md), generated scoped MCP

runtime and application. The earlier [direct adapter experiment](../tactical/127-opus-sky-computer-use.md)

## Failed attempts and evaluation correction

The first attempt stopped before model launch because automatic discovery
found no expanded runtime configuration in the guest cache. Its approximately
91.5 seconds of lifecycle cost remain retained. Explicit selection of a
private expanded installation manifest subsequently passed artifact checks
and startup probing; vendor code was not patched.

A second setup session generated and probed configuration but did not register
it with YA. The setup gate correctly blocked the task session. That attempt
cost 26.125 agent seconds, 6 calls and 104.72 lifecycle seconds; token components
were 14 uncached input, 42,661 cache write, 243,129 cache read and 1,777 output
(including 153 reasoning). The guide now states YA host context and scoped
registration authorization explicitly. Merely writing an MCP file does not
make tools available to a running host.

Successful trials used source pin `e9a51f38401dd455bb84137b4a3ee4e94a7f54fd`.
Their original receipts incorrectly failed a teardown check that confused
native-runtime closure with the still-serving MCP wrapper's later process
exit. Commit `dbf6e1b` separates these events. A narrow hash-bound evaluator
accepted the preserved trials only after checking known bridge/verifier
sources, fresh scoped closure evidence, successful close acknowledgement,
setup artifacts, unchanged source/runtime pins, independent effects, manual
route review, stopped owned processes and workspace disposal. Original failed
receipts and costs remain unchanged; derived corrected records pass. This was
an evaluation correction, not replacement of an unsuccessful task run.

A subsequent startup-only check exercised the revised bridge against the genuine
installed runtime. After initialize/list/sky_close, the native closure marker
and event existed while the wrapper remained alive; wrapper exit was recorded
only after stdin closed, and its process was reaped. This validates the forward
teardown event ordering without another model or GUI task.

## Limits

One task recovered from a ScreenCaptureKit capture error using accessibility
observations. Neither fresh task transcript retained inline image blocks;
these runs do not newly qualify media delivery. Earlier direct-adapter image
evidence remains separate. A final screenshot for the save task was obscured
by unrelated guest onboarding; its independent file oracle establishes the
save effect. Unrelated prompts were left untouched.

Two tasks with one repetition each establish a usable bounded route, not
performance superiority, broad application reach, host portability, or
non-interference. Runtime availability and the host's supported MCP loading
mechanism remain prerequisites. No proprietary runtime is redistributed.
